### Refactoring

**You own the contract. The structure changes; the behavior does not.** For "refactor", "rename", "extract", "inline", "dedupe", "restructure", "move this module", "tidy up this area". Distinct from Feature, which adds behavior, and Bug fix, which corrects it.

A refactor that smuggles in a behavior change loses its safety net. If the cleanup reveals a missing feature or a real bug, split it out and ship the structural change first against the pinned contract. A redesign is allowed, but name it and route to Feature. Large or cross-cutting structural work belongs to `$deepwright:figure-it-out`; this playbook is the focused-to-medium change.

1. Pin the behavior contract first. Invoke `$deepwright:how` over the affected subsystem to learn the contract, then write a characterization test, snapshot, or equivalence harness that captures current behavior before any structure moves. The harness makes "refactor" a checkable claim (`$deepwright:principle-prove-it-works`). If the area has no coverage, write the pin before touching structure. Type check and lint are not a pin.
2. Name the structure the code is missing per `$deepwright:principle-model-the-domain`: a state machine over scattered booleans, a table or registry over spread-out branching, a typed model over repeated shape assumptions, or a reducer over ad hoc mutations. Boring code stays when the shape is already clear and local; the reshape must delete branches or invalid states, not add indirection.
3. Name the target shape. State what the module layout, types, and call graph should be if built today (`$deepwright:principle-foundational-thinking`, `$deepwright:principle-redesign-from-first-principles`). If the target crosses a function boundary, invoke `$deepwright:architect` for design exploration before the move.
4. Subtract before you add. Delete dead weight, collapse one-caller wrappers, drop redundant validators, and remove orphan references before introducing the new shape (`$deepwright:principle-subtract-before-you-add`). The smallest change that reaches the target shape ships (`$deepwright:principle-laziness-protocol`). A speculative cleanup that "might help" gets reverted, not left to ride.
5. Move in small behavior-preserving steps, each keeping the pin green. For API reshapes, migrate every caller and delete the old API in the same wave (`$deepwright:principle-migrate-callers-then-delete-legacy-apis`). Avoid compatibility shims and parallel old-and-new paths unless the public migration contract requires them. Spot-check every rename against actual files, strings, prose, and back-references. When collaboration tools are available, delegate mechanical edits to a subagent with exact paths, names, and the behavior to hold, then review the diff. Otherwise make the edits sequentially and run a separate search-and-review pass. Never require a particular model.
6. Prove behavior is unchanged on the real artifact, not "it compiles" (`$deepwright:principle-prove-it-works`). For larger reshapes, run an equivalence check: a script that diffs old-vs-new outputs, a recorded baseline replayed against the new code, or a smoke run using an available host control capability. Own the verification yourself; do not trust a delegate's "looks good" summary.
7. Confirm the change earns its place. The success measure is reduced reader load (`$deepwright:principle-minimize-reader-load`): fewer layers between question and answer, less hidden state, fewer indirections without a second consumer. If the diff does not lower reader load somewhere, revert it.
8. Rebase into small ordered commits that tell the story only when history rewriting is safe and authorized; otherwise add ordered commits without rewriting shared history. Shape them with `$deepwright:principle-sequence-verifiable-units`, so each behavior-preserving slice stays green before the next. Run **Opening a PR** only when the user asked for a PR.

**Reply:** the structure that changed, the pin you held it against, the equivalence proof, the reader-load delta, what shipped and what got reverted. No new behavior.

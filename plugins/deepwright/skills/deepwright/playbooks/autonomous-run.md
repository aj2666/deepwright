### Autonomous run

**You own the exit condition. Define done, then drive to it for the current run.** For "run until done", "keep iterating", or another bounded autonomous task. Do not promise work after the current Codex turn or session. If the host cannot continue, leave a durable checkpoint for the next invocation.

1. State the exit condition as a checkable predicate before the first iteration (tests green, repro fixed, all N authorized PRs merge-ready, pixel-diff zero). Include merged PRs only when the user explicitly authorized those merges. A vague goal stalls; a predicate lets you stop.
   Set a proportional iteration/retry allowance and deadline when the task needs a timebox. For work spanning sessions, the optional [run evidence helper](../references/run-evidence.md) preserves the same allowance and selected evidence across resumes. Claim an iteration before starting it; failed attempts still consume their claim. Never invent token or cost measurements the host does not supply.
2. Pick a bounded wake mechanism the host actually exposes. For GitHub events, prefer the available GitHub connector or authenticated `gh` watch commands. Use a host wait or monitoring capability only when available. Otherwise make one status pass, checkpoint, and report when to resume; never invent a persistent background loop.
3. Each iteration makes the smallest change the evidence justifies, verifies it against the predicate, commits if it advanced, discards changes that didn't help. Belt-and-suspenders that "might help" gets reverted, not left to ride.
   Sequence the work via `$deepwright:principle-sequence-verifiable-units`, verifying each unit before the next instead of batching checks at the end.
4. Keep discoveries inside the authorized scope. Fix blockers that are necessary for the stated predicate and reversible within the current workspace. Record unrelated defects as follow-ups instead of changing them. Pause for destructive actions, external side effects not already requested, credential or permission changes, scope expansion, or a product decision no experiment can settle. Use the host's user-input mechanism when a decision is required.
5. Checkpoint every iteration via `$deepwright:show-me-your-work`. Store the run ledger under `.deepwright/runs/<run-slug>/decisions.tsv`, with one row for what changed and whether the predicate moved. Keep secrets and raw private content out of the ledger.
   Reuse any run evidence records rather than duplicating captured files. Keep historical inputs separate from fresh observations and report material [coverage gaps](../references/evidence-coverage.md).
6. Stop when the predicate is met, the user stops the run, the agreed allowance is exhausted, the current session cannot continue safely, or the work reaches a genuine dead end. On a plateau, try a bounded alternative within the remaining allowance rather than spinning, and never relax the predicate to declare victory.

**Reply:** the exit condition, iterations run, what landed, what was discarded, final predicate state.

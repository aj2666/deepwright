### Specification

**The deliverable is a buildable contract, not an implementation.** Use for a
request to define behavior, requirements, or acceptance criteria before coding.

Read [Spec](../../spec/SKILL.md) in full and apply its grounding, clarification,
and acceptance-contract workflow. Reuse an existing specification rather than
creating a parallel one. Return the result in the conversation unless writing
a document is authorized. Report unresolved decisions and stop after the
specification; do not start Feature, publish tickets, or modify product code
without a request covering those actions.

# Keep lessons scoped to their evidence

Use when reflection finds a durable pattern worth carrying into future work. Propose one recognizable trigger and one decision-changing action per lesson. A single incident may justify a narrow correction; it does not establish frequency or a universal rule.

Keep the proposal in the conversation by default. When saving lessons is already authorized, use the project's existing learning or skill convention; otherwise ask only before applying the proposed write. Existing explicit approval to implement the same improvement remains sufficient. Do not create hooks, background observers, transcript collectors, or personal/global rules as a side effect of reflection.

Retain these fields in a saved or proposed lesson:

| Field | Content |
| --- | --- |
| Scope | Project and owning skill; include relevant runtime or version constraints |
| Trigger → action | A future agent can recognize the condition and choose the response |
| Evidence | Supplied task/run identifiers and minimal source or receipt pointers; what failed and what corrected it |
| Counterexamples | When the action is unnecessary or wrong; contradictions and unresolved alternatives |
| Verification | Last verified revision/context and observed result, or explicitly unverified |
| Status | Proposed, approved, superseded, or retired, with the applicable decision source |

Before proposing a body change, read the owning skill and check whether it already covers the behavior. Repeated failures despite existing instructions may need a better trigger, a moved reference, or a structural check instead of another paragraph. For recurrence across supplied evaluations, use [failure analysis](failure-analysis.md); counts prioritize investigation and do not approve edits.

Revalidate a lesson when its trigger, dependency, or operating context changes. Preserve contradictory evidence and narrow, supersede, or retire the lesson when it no longer fits. Do not assign invented confidence percentages or auto-promote based on age or a count threshold. Promotion beyond one project requires evidence from the proposed wider scope and explicit authorization for that destination.
